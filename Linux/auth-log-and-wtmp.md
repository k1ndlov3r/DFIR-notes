# Linux Authentication Artifacts: auth.log and wtmp

## Initial Analysis

When investigating a Linux system, authentication-related logs are often among the first artifacts examined. They provide valuable insight into user activity, authentication attempts, remote access, and privilege escalation events.

This note focuses on two important authentication artifacts:

1. **auth.log**
2. **wtmp**

---

# 1. auth.log

The `auth.log` file records authentication and authorization events on Linux systems. Whenever a user attempts to log in, switch users, perform privileged actions, or access services requiring authentication, relevant entries are typically written to this log.

Common events recorded in `auth.log` include:

* SSH login attempts (`sshd`)
* Successful and failed authentication attempts
* Privilege escalation events (`sudo`)
* User account authentication activities
* Service authentication events

**Default location:**

```bash
/var/log/auth.log
```

## Fields in auth.log

A typical `auth.log` entry may contain the following information:

* Date and time
* Hostname
* Process ID (PID)
* Username
* Authentication status
* Source IP address or hostname
* Log message

# 2. wtmp

The `wtmp` file is a binary log that records user login and logout activity, along with system boot and shutdown events.

Unlike `auth.log`, the contents of `wtmp` are not directly human-readable because the file is stored in binary format.

**Default location:**

```bash
/var/log/wtmp
```

## Information Stored in wtmp

The following information can typically be extracted from `wtmp` records:

* Username
* Terminal (TTY/PTS)
* Login time
* Logout time
* Session duration
* Source IP address or hostname

# Reading wtmp Records

Linux provides utilities such as `last` to read `wtmp` records. However, investigators may encounter issues when analyzing a `wtmp` file collected from a system that uses a different CPU architecture than the analysis workstation.

In such situations, parsing utilities may not correctly interpret the binary structures stored within the file.

To address this issue, investigators can use a conversion tool such as `utmp.py` to decode the binary records into a human-readable format.

Example:

```bash
python3 utmp.py -o wtmp.out wtmp
```

This command generates a text output file named:

```text
wtmp.out
```

The resulting file can then be reviewed using standard text-processing tools such as:

```bash
cat wtmp.out
less wtmp.out
```

---

# Understanding utmp.py Output

The decoded output generated by `utmp.py` contains several fields that help investigators reconstruct system activity.

### Important Fields

**Type**

* Indicates the record type, such as user login, logout, system boot, or shutdown.

**PID**

* Process identifier associated with the event.

**Line**

* Terminal line (`tty` or `pts`) used by the session.

**ID**

* Short identifier associated with the terminal line.

**User**

* Username associated with the event.

**Host**

* Hostname or IP address from which the user connected.

**Exit**

* Exit status associated with the session or process.

**Session**

* Session identifier.

**sec**

* Timestamp of the event.
* Investigators should remember that timestamps are displayed using the analysis system's timezone, which may differ from the timezone of the original system.

**usec**

* Microsecond component of the timestamp.

**Addr**

* Additional address information, often containing the source IP address for remote logins.

# DFIR Relevance

Both `auth.log` and `wtmp` are valuable forensic artifacts that help investigators establish user activity timelines and identify suspicious behavior.

### auth.log

Useful for identifying:

* Failed login attempts
* Brute-force attacks
* Successful authentications
* SSH activity
* Privilege escalation through `sudo`
* Authentication-related errors

### wtmp

Useful for identifying:

* User login sessions
* User logout sessions
* System reboots
* System shutdowns
* Session durations
* Remote access activity

### Correlation Opportunities

By correlating data from both `auth.log` and `wtmp`, investigators can:

* Reconstruct attacker timelines
* Validate account usage
* Identify unauthorized access
* Confirm persistence activity
* Investigate lateral movement and remote access events

---

# Conclusion

Authentication artifacts are often among the most valuable sources of evidence during a Linux forensic investigation. While `auth.log` provides detailed authentication events, `wtmp` offers a historical record of user sessions and system activity.

Together, these artifacts help investigators build accurate timelines, identify suspicious behavior, and better understand how a system was accessed and used.
